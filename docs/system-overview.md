# Как работает мини-CRM «Объекты и задачи»

Система помогает руководителю строительной компании распределять работу по
объектам и проверять результат. В ней есть две роли: постановщик и исполнитель.
У каждого пользователя свой вход по электронной почте и паролю. Свободная
регистрация закрыта: учётные записи и роли заранее создаёт администратор.

Постановщик видит все объекты и задачи. Он добавляет стройку с названием и адресом,
создаёт внутри неё задачу, указывает описание и назначает исполнителя. При
необходимости он может исправить название и описание, удалить задачу или объект.
Перед удалением интерфейс запрашивает подтверждение. Удаление окончательное:
вместе с объектом исчезают его задачи и история; вместе с задачей — её история.

Исполнитель видит только назначенные ему задачи и связанные с ними объекты.
Задачи других сотрудников скрыты, даже если относятся к той же стройке.
Исполнитель не может сам назначить другого сотрудника, изменить описание
или принять собственный результат.

Новая задача сначала переходит в работу, затем исполнитель отправляет её на
проверку. Постановщик принимает результат либо возвращает задачу на доработку,
обязательно объяснив замечания в комментарии. После исправлений исполнитель
снова отправляет результат на проверку. Принятая задача завершает этот цикл.

Доступ проверяет сама база данных, то есть место хранения информации. Поэтому
прямой запрос в обход экрана не даёт исполнителю чужие задачи. Смена статуса
тоже проходит серверную проверку: нельзя пропустить этап, принять свою работу
или выполнить действие за другого исполнителя.

При каждой смене статуса система сама записывает участника, время и результат.
Изменение статуса и запись истории сохраняются вместе: если одна часть не
выполнена, другая также отменяется. Пользователь не может напрямую дописать,
исправить или удалить событие истории. В карточке видны email участников
и комментарии к возвратам.

Постановщик вправе переназначить задачу на любом этапе, даже после приёмки.
Статус и история сохраняются. Новый исполнитель получает доступ, прежний теряет
его при следующем запросе. Уже открытый экран сам мгновенно не обновляется:
для демонстрации смены доступа нужно обновить страницу.
