# Smoke checklist — Foundation

Ручной список для проверки этапа 1. Он не подтверждает безопасность будущей БД.

1. Выполнить `npm ci`, `npm run check`, затем `npm run dev`.
2. Открыть `/`: адрес меняется на `/objects`, видны заголовок «Объекты» и пометка Foundation.
3. Перейти по меню «Мои задачи» → «Вход» → «Объекты». Проверить заголовки,
   активный пункт и работу браузерных «Назад»/«Вперёд».
4. Ввести напрямую `/objects/demo-object`: видна карточка объекта и `demo-object`.
5. Ввести `/tasks/demo-task`: видна карточка задачи и `demo-task`.
6. Обновить обе карточки: Vite возвращает SPA, нужный экран сохраняется.
7. Открыть `/unknown`: видна страница «Страница не найдена»;
   ссылка «Перейти к объектам» работает.
8. Сузить окно до 375 px, затем проверить обычную ширину. Нет горизонтального
   скролла, меню переносится, тексты читаются. Перейти по ссылкам клавишей Tab:
   фокус виден, Enter открывает маршрут.
9. В DevTools Console нет ошибок приложения. Во вкладке Network нет запросов
   к Supabase или другому backend; экраны не запрашивают пароли и реальные данные.
10. Остановить dev-сервер, выполнить `npm run build`, `npm run preview`.
    На адресе preview повторить прямой вход и обновление `/tasks/demo-task`.

Для будущего хостинга отдельно проверить fallback глубоких URL после размещения.
Авторизация, CRUD, права двух исполнителей, переходы и история проверяются только
в следующих этапах после реализации; этот checklist их не покрывает.
