# ADR-001: Архитектура мини-CRM

Дата: 2026-11-05. Статус: Proposed (сохранён из архитектуры, предоставленной пользователем).

## Контекст

Небольшая CRM с двумя ролями, защищёнными данными, ограниченными переходами
статусов и аудитом действий.

## Решение

React SPA + Supabase Auth + PostgreSQL с RLS. Чтение через Data API
(PostgREST), критические изменения через защищённые SQL-функции, вызываемые
через RPC того же API.

Клиент: React + TypeScript + Vite, React Router для маршрутов, TanStack Query
для серверных данных при подключении API. TanStack Query не заменяет авторизацию
и проверки БД. В Foundation нет запросов, поэтому QueryClient и зависимость
TanStack Query добавляются на этапе подключения данных.

Изменения статусов и переназначение исполнителя относятся к критическим
изменениям. Прямое обращение к Data API не должно позволять обход этих функций.
Обычный CRUD допускается только в пределах грантов, RLS и ограничений БД;
конкретные SQL-привилегии будут заданы миграциями следующего этапа.

## Альтернативы

- React + NestJS + PostgreSQL.
- React + Supabase Edge Functions.

## Обоснование

Минимизируем инфраструктурный код, сохраняем проверку прав на серверной стороне
и используем транзакционность PostgreSQL.

## Последствия

Быстрый MVP, но бизнес-логика частично перемещается в SQL. Потребуются миграции,
тесты политик доступа и контроль привилегий. Хостинг SPA должен возвращать
`index.html` для глубоких ссылок. Отдельный собственный backend не требуется.

## Реализация Foundation

- `src/app` — оболочка, маршруты, стили; `src/pages` — экраны;
  `src/shared/ui` — общий UI; `src/test` — настройка тестов.
- Tailwind CSS v4 с Vite-плагином и shadcn/ui; тема и глобальные правила
  в `globals.css`, компонентные стили — utility-классы в JSX.
  Дополнительные слои вводятся только при конкретной потребности.
- Строгий TypeScript, ESLint, Vitest + Testing Library + jsdom.
- `npm run check`: typecheck → lint → tests → build.
- Node 24 (`.nvmrc`), зависимости зафиксированы в `package-lock.json`.
- Все будущие изменения БД — в `supabase/migrations/*.sql`.

В этапе 1 реализованы только оболочка и заглушки. Supabase SDK, QueryClient,
сессии, запросы, CRUD и SQL отсутствуют. Открытые маршруты заглушек не определяют
прав доступа финальной CRM. Правила удаления и переназначения — [ADR-002](ADR-002.md).
